# LifeBook：回忆访谈与长期接续

## 产品流程

书架只放用户正在写的书。进入一本书后，优先展示「接着上次聊」，下面可以开始新的回忆方向。新建一本书后先停在选择页，不自动打开麦克风。

一次聊天选择「人生阶段 + 回忆主题」：

- 阶段：不限阶段、童年、少年、青年、中年、晚年。无需填年龄。
- 主题：成长的地方、求学时光、家人与朋友、工作与事业、人生转折、日常的珍贵片段。
- 选择后可用语音或文字开始。聊天页标题显示当前方向，可以换方向、暂停和结束。
- 换方向保留本次聊天的原话；开始另一段回忆会新建一次会话。
- 聊过的故事按方向列出；原有未选方向的记录标为「自由回忆」。
- 回忆与纠错保存可核对的原话线索，书稿与出处用于整理章节，两者不挤占聊天入口。

## 主持方式

首次简短介绍自己，然后直接围绕所选主题问一个容易回答的回忆问题。由生活背景进入具体事件，再顺着人物和经过往下问；只有对方愿意时才追问意义和感受。用户偏题时先接住意思，在自然停顿处回到主线，不把采访变成考试计划或近况调查。用户明确换题时跟随，不强拉提纲。

## 记忆如何接续（本版已实现）

本机原话是来源。每次重新构建资料时，扫描本书全部可用用户记录，优先使用用户纠正后的线索，排除删除、拒绝和避谈内容，再选择：

1. 当前回忆方向和讲述者称呼。
2. 最多12次聊天的首尾片段，作为简短的历次线索；会话较多时按时间采样。
3. 与当前话题词语相关的历史片段，来自整本书，而非只取最近几条；附来源标识和核对状态。
4. 最近10条对话，保留当前问答进度。

这是基于原话的检索与摘录，不是把生成摘要当成事实。旧记录不因上下文变短而从本机删除；没有维护容易过期的独立摘要副本，纠错和删除下次构建时即生效。

OpenAI语音在最终转写保存后查找旧回忆，再请求模型回答；这可能比直接自动回应多一点等待。千问连接时读取相同资料，并在每轮回答结束后更新下一轮资料；没有宣称验证了千问同轮检索时序。文字聊天每次请求也会重新查找。

## 当前边界

- 检索采用中文分词与词语匹配，不是向量语义搜索。完全不同的说法或没有明确线索时，仍可能漏掉相关往事；不承诺永不遗忘。
- 历史概要是采样摘录，不保证涵盖人生中所有人物和事件。全文仍在本机。
- 没有改变模型上下文上限。服务商连接断开后，可以重开语音并根据本机记录接续；本版没有完成连续一小时以上真人语音实测。
- 模型可能重复提问或误判主线，仍需观察实际听感和长时对话。原有拒绝话题流程会停止语音，重新开启后移除旧话题上下文。

## 书架整理与测试隔离

原有5本「连接测试（虚构素材）」移出书架，完整备份保存在 local-data/cleanup-backups/2026-09-29。可在设置的「已移出书架」恢复。用户原书和会话保留。

自动化测试使用独立临时数据目录。真实连接测试脚本在 finally 中移出测试书，防止再次堆满首页。

## 验证记录

- 26项自动化测试通过，包括500条历史检索、纠正覆盖旧说法、拒绝/删除过滤、主题持久化、归档恢复、语音先检索后回应。
- 真实 gpt-realtime-2.1-mini：少年/求学主题开场收到382516字节音频，围绕老师发问。
- 真实语音模型：300条虚构历史后，成功回答早期小卖部老板娘为「周阿姨」；使用文字输入和音频输出，没有采集用户麦克风。
- 浏览器实点：书架清理、新建不自动录音、少年与求学选择、进入文字访谈，均已看到实际结果。

## 聊天滚动

聊天记录在固定高度区域内滚动，输入框和语音控制保持可见。停在底部时，新消息自动跟随；向上查看历史时保留阅读位置，并显示「回到最新消息」。主动发送文字时回到底部。文字发送前如正在语音，会先保留输入内容，再停止语音，避免刷新时丢掉草稿。
